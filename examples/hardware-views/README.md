# 用真实可停顿 RTL 检查三种阅读模式

`rtl/add_const.sv` 来自通用 tiny-stream fixture。模型只记录当前 8 位、加 3 配置的端口、组合表达式和两个真实寄存器；保留 as_built/partial，不自动批准。`sum_value` 是有源码依据的派生表达式节点，不是额外的 RTL 网络或寄存级。

在复制的样例目录运行 `rtlarch open --workspace . --json`，使用返回的链接：

1. **架构通路**：找到保存输出载荷、输出有效状态的位置；寄存状态不会为了简化而消失。
2. **内部状态与运算**：展开输入加三、可接受条件和对外有效表达式。指出输出停顿时哪些输入参与状态更新；当前模型只记录输入集合，不能把所有空心箭头当作数据线。
3. **原始连接**：逐条核对端口、位宽、方向。此模型是原始 signal 接口，不会根据 s_valid/m_ready 等名字自动生成 RV 通道。

再打开 `examples/tiny-stream` 的 path 层，比较它已有的原生 rv 接口：通道标识说明 data/valid 正向、ready 反向；点击查看成员。模型声明不代表仿真已证明。

框图检查分别报告连接对应、语义待核对、基本几何和阅读拥挤。状态输入集合的角色缺失会明确提示；这不是通过看图获得的 RTL 等价证明。布局距离、阅读分区与物理延迟没有对应关系。
