# 1.3：架构承诺与当前证据

采纳本次评审中可落地的四项建议：缩小任务上下文、细化变更影响、把有限行为承诺变成可执行检查、比较设计与当前 RTL 展开。保留已有架构阅读能力；不引入另一份权威模型、复杂审批流程或新的生产依赖。

| 使用问题 | 本次实现 |
|---|---|
| Agent 每次读取大模型和重复 Markdown | `context-index` 分页导航；`context --purpose` 按任务优先级组合局部数据；明确字节预算、省略入口，关键未知装不下时报错 |
| 一次合同修改显示整个对象，不知要复核什么 | 合同、端口和绑定按字段比较；预览及 `compare` 给出直接变化、声明依赖、验证义务和原验证计划 |
| 有合同，但没有证据说明 RTL 是否执行它 | IR 3 可选 obligations；`checks` 生成三类有限仿真监视器，`verify` 保存触发结果、当前输入和产物摘要 |
| 模型参数、端口与 RTL 可能各说各话 | `conform` 对当前 Yosys 展开和显式映射输出 MATCH / MISMATCH / UNKNOWN |
| “批准”“通过”容易混淆 | `assurance` 和模块“行为约定”中独立显示本地审阅、结构和行为；最新失败优先，过期输入不能继续通过 |

## 实际怎么用

先 `resume --offline` 恢复任务，再用 `context-index --offline --limit 30` 找模块。对局部修改使用：

```bash
rtlarch context --module fifo --purpose implementation --max-bytes 12000 --offline --workspace <项目> --json
```

预算单位是 UTF-8 字节，包含 CLI 返回的工作区信息；不是 token 精确计数。`purpose` 支持 design、review、implementation、debug。返回关键合同与未知，其他部分整体保留或带计数省略，不静默截断。旧 `context` 仍提供完整兼容输出。索引只做导航，不能当成完整上下文。

通过通常的提案流程在 `contract.obligations` 声明待检查行为；写 RTL 引脚绑定后生成检查器。直接照着 [通用 FIFO 示例](../examples/contract-checks/README.md) 在复制的临时工作区运行，可观察生成、仿真、展开、一致性比较和页面状态。详细语义见 [skill 验证方法](../.agents/skills/rtl-architect/references/verification.md)。

页面打开模块详情 → 行为约定 → 核验状态。该区域按需读取，显式刷新；不会为每次选择重跑命令。候选页明确没有当前保存版本的核验证据。审阅记录仍是本地文件，身份未经认证；没有包装成安全认证系统。

## 故意限定的范围

- 监视器只支持单实例、同域同步复位的 RV 保持、复位后输出为空、原样 FIFO 顺序/容量/测试末尾排空。不是通用 SVA 生成器；没有触发就失败，不把空检查当通过。
- 结构比较覆盖显式映射模块、非负整数参数、端口和可比较的直接连线。数组、黑盒、不明确编码和复杂内部逻辑保留未知；映射外模块单独列出，不声称整个设计匹配。
- 输入闭包由作者声明，工具核对声明文件与产物摘要，不自动发现全部 include、脚本、环境或宏依赖。命令与映射本身仍需审阅；本地记录没有签名防伪。
- 全模型 hash 变化仍使旧验证过期。影响列表帮助安排复核，没有用增量算法豁免其他检查。最多回看最近 100 次运行/结构报告。
- 本轮没有加入 AXI 属性库、formal 引擎、外部认证审批或全局缓存重构；先测量局部读取，再决定是否改造核心索引。

旧 IR 1/2/3 不自动补 obligations 字段，原模型语义 hash 保持兼容。现有真实工作区和服务不自动迁移或重启。版本为 1.3.0；本轮本机检查结果见 [VALIDATION](../VALIDATION.md)。
