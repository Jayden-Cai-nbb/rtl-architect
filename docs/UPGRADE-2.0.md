# 2.0.0：看清结构，也看清证据缺口

这个里程碑收敛四个实际缺口：密集边界走线、局部重测遮住旧失败、多实例缺少外部对照，以及新用户面对过长版本历史。没有把“任意 RTL 自动理解”列为完成能力。

## 本轮实现

| 缺口 | 改进 | 验收方式 |
|---|---|---|
| 并排寄存器的接口集中在图顶端，长线反复折返 | 边界组按真实连接对象分布；边界专用端口朝向输入/输出侧；通道增加固定间距候选。网页和 SVG 同源，布局不改变连接 | 同一 1.9 样例、相同保存位置对比；六类架构、三种模式检查 |
| 大图默认放大后主线可能仍在屏外 | 阅读比例下，纵向定位到主线起点的中心 | 正常桌面窗口打开无保存视野的长图 |
| 最新报告只重测一项，会隐藏其他状态失败 | 对每个声明了 update 的状态分别取最新证据；局部重测和空映射发现不会清除其他结论；未比较、过期、未知分别计数 | 部分通过、失败、发现、源码变更、损坏报告与修复回归 |
| 相同 RTL 定义的不同实例容易混淆 | 清单 v2 显式列 scopes/instancePath；跨实例不混用局部 bit ID，结果保留路径；v1 仍支持 | 两个同参数上游实例；重复映射、缺失路径必须不能通过 |
| 只有自编示例，不能说明实际适用性 | 固定提交的 MIT `verilog-axis/axis_register` 原文件，双级 wrapper、独立事务队列、故障与修复 | 单步核验与实际仿真分别记录；不靠模型生成自己的参考答案 |
| 首次安装、升级和阅读入口不集中 | README 收敛到当前能力、三种任务和短入口；历史移到版本索引；干净副本安装和打开检查 | 不携带 dist、node_modules 或本机 runtime 的副本验收 |

## 使用变化

`observe-state` v1 清单不需改写。需要多实例时使用 `schemaVersion: 2`，保留 runId/netlist/top，将 instancePath 和 mappings 放进 scopes 数组。参见 [可运行双实例样例](../examples/external-axis/README.md)。最多 16 个作用域、总计 32 个映射、64 项发现明细；每个实例独立比较，不做跨层逻辑锥拼接或时序等价。

网页“行为约定 → 核验状态 → RTL 状态比较”按状态列出结论、实例路径、证据依据、反例和记录。汇总分母为模型中声明了更新规则的寄存器，不是整颗芯片。还会展示参与比较作用域发现的 RTL 状态数，未建模状态仍是缺口。`--module` 仅汇总所选模型模块。

比较器版本升为 `yosys-proc-bdd-v2`：1.x 的旧比较记录保留，但显示过期，需要在当前版本重新展开/比较。旧模型、批准和布局格式不迁移，不改变既有模型 hash。安装后保存网页未发送内容，再对自己的工作区执行 `rtlarch open --restart --workspace <项目>`；不要重启别人的项目。

## 外部对照的实际意义

REG_TYPE=1 原始 proc 产物包含不可选择分支中的 X。工具仍将它报为 UNKNOWN。样例显式运行 Yosys `opt_muxtree` 消除控制条件不可能选中的分支，保留 `$dff` 与字级逻辑；没有用 `setundef` 或任意值替换 X。前端命令、文件摘要和版本进入本次生产记录。

同样重要的是：两个级都把数据异或 1，端到端结果会抵消，事务队列可通过，但两个局部状态比较仍报差异。两个级各加 1 则同时被局部比较和端到端队列发现。因此，局部合同与事务验收互补，任何一种绿灯都不能代替另一种。

## 尚未完成的承诺

密集交叉互连仍需要分层、分组和选择重点；图形通过不代表可读性验收。外部样例仅覆盖 REG_TYPE=1、8 位、禁用 sideband、两个实例及有限事务场景；不覆盖 skid buffer、任意参数、初值、四态、跨时钟、全 AXI 协议或完整顺序等价。

真实用户读图时间、发现错误的效率仍需实际试用，不能用维护回归数字替代。[本轮验证记录](../VALIDATION.md) 只列本轮真正执行的检查；远程 CI 与 GitHub 推送单独说明。
