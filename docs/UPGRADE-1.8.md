# 1.8：让阅读意图进入布局和检查

本轮继续评审路线中的复杂图可读性。1.6/1.7 的验证依据、状态观察与反例保持；本轮把“先理解结构再排图”落实为工具约束，避免仅靠增大间距或不断拖框。

## 现在如何使用

默认自动布局仍作为起点。Agent 核对源码及模型后，按需在独立 layout 的 reading 中声明并排分支、共享资源、外侧返回，与已有主线和阶段一起安排。用户可先阅读样稿、选择更关心的事务，再要求调整；无需理解全部配置字段或逐项审批。

并排组临时收成排序单元，再展开真实节点；共享资源保持一个实例，放到使用方旁边或下方；返回线保留真实方向并使用指定外侧通道。四侧端口、标签和间隔共同测量。顶部输入边界现在也为表达式依赖的完整线名留空间。端口锚点使用所在模块自己的分组，避免不同来源恰好同名而把两个操作数画到同一个输入点。

`diagram-quality --workspace <项目> --module <层级> --json` 只读生成质量记录，可加 `--model` 与 `--layout` 检查候选。页面和离线包同时报告布局约束是否满足，指明需要调整的对象；保存的手动位置不会被检查器自动改写。只有内部状态的层级也按完整可见节点安排。

## 证据与取舍

[历史验证摘要](evidence/1.8.0/README.md)覆盖流水、分支汇合、固定优先级仲裁、共享 RAM、累加器和单槽 FIFO。独立 Yosys 展开核对实例与物理连接，三种视图核对几何、对应、约束和选择稳定；同时保留默认布局对照。没有因为某个指标变好便声称所有图都更好。

图形检查、声明约束、语义未知和使用者阅读结果分别记录。仲裁和共享访问仍可能出现交叉；原始连接模式用于核对端口，不承诺所有名称同时铺开。真实状态来自 IR，分区不添加寄存级，几何返回不证明可达反馈。并排不证明无数据依赖，共享不证明 RAM 端口/仲裁能力。

## 兼容与后续

三个字段均可选，不修改 IR 语义、模型 hash、批准或旧布局文件。仅使用旧字段时继续原有布局路径。新字段冲突、错误关系和旧版本引用明确拒绝；不会猜测任意 RTL 的全部微架构。已有完整手动坐标优先，应用新布局需显式“自动布局”或生成未给位置的新包。

后续应以真实使用者读图反馈挑选具体难例，扩充有来源的基准，再处理密集控制扇出和跨层共享。类型/四态语义与更大范围状态等价仍需独立推进，不能借布局升级扩大验证结论。
