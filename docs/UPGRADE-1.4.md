# 1.4：让关系的含义先于布局

本轮采纳评审中的核心建议：在原模型之上形成只读硬件关系投影，以不同阅读目的生成框图；几何完整、语义清楚和 RTL 正确分别核对。保留现有 ELK、端口规划与路由器，没有把更换算法当成自动理解硬件。

## 已实现

| 问题 | 改进 |
|---|---|
| 两端业务分类不一致时任选一方 | 明确显示冲突，保留两端名称；不会误作时钟/配置而折叠 |
| RV 箭头让人误以为全部信号同向 | 原生 rv 接口投影为声明的逻辑通道，图上标出 data/valid →、ready ←；点击查看成员与证据关联 |
| 状态输入看起来像精确的数据线 | 状态输入集合标为“状态依赖”，使用空心箭头；明确未表达数据/使能/取消及逐位更新关系 |
| 所有内容挤在一个抽象层 | 三种模式共用 IR、投影和路由；原始连接逐条显示并给非边界端口独立锚点，不按业务组混并 |
| 控制器或存储按类型被放错位置 | 分类不明的控制器保留在主拓扑；携带数据/RV 的存储不当附属资源挂起 |
| 布局不知道最终走线是否拥挤 | 小图自动布局有一次有界间距试探，优先比较穿框/未路由、隐藏标签、交叉、共线与长度；无改善就保留原布局 |
| 图形 PASS 被误当成“看懂了” | 连接对应、语义待核对、基本几何和阅读拥挤分别呈现；人工阅读始终单列 |

原生 rv 的三个成员来自现有接口协议定义，不是从信号名字推断。它只表示**模型声明**，不称作 verified；1.3 的结构/行为核验仍独立进行。没有直接连接证据时明确显示缺关联，已有 evidenceIds 也不自动证明证据新鲜。

## 怎么阅读

画布“阅读模式”选择：

- **架构通路**：模块与主要关系；保留已有真实状态边界及驱动模块的组合逻辑，其余内部表达式按需展开。
- **内部状态与运算**：显示模型已有的全部内部表达式与状态；不自动画不存在的 MUX、存储或寄存器。
- **原始连接**：展开时钟/配置及内部逻辑，每条记录独立可追溯，显示原端点与位宽。原生 rv 仍是模型逻辑接口，不能冒充已知 RTL 引脚名。

当前会话中各模式保留自己的位置与视口。普通选择不重画，缩放不改变几何；模式切换可以改变可见拓扑。保存/下载布局保存当前位置，模式本身不写入权威模型。SVG 导出保留当前模式、相同走线及依赖箭头；离线 bundle 默认仍是架构视图。

“框图检查”可以展开具体冲突、状态粒度缺口和 partial 提示。没有冲突也只是“未发现”，不是人工读图通过。原始连接未画出时必须有折叠原因；图对模型的连接对应完整，不代表模型已覆盖全部 RTL。

[真实通用 RTL 阅读样例](../examples/hardware-views/README.md)提供可停顿加常数级：先找两个寄存器，再展开可接受条件和加法表达式，最后逐条对照端口。用于验证图的语义表达，不是新增 RTL 行为证明。

## 有意保留的边界

未增加任意原始信号的自动协议识别、通用 request/response 配对、寄存器角色推断或门级电路生成。没有依据就保留未知。组合 MUX 的选择端只能从现有明确表达式读取，不能从 enable/grant 等名字推断。

没有改成 ELK FIXED_SIDE，也没有引入全局 rip-up-and-reroute。一次间距试探只用于最多 26 个显示节点、60 条显示关系的小图自动布局；显式 reading、保存位置及更大图保留原路径。它保持相对顺序，不新增/删除连接，不保证复杂图无交叉，也不是全局最优布局。

原模型不新增默认字段，IR 1/2/3 的语义 hash 继续保持。真实工作区不自动迁移或重启。本轮实际检查与截图见 [VALIDATION](../VALIDATION.md)。
