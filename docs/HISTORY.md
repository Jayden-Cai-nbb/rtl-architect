# 版本沿革与迁移

本页汇总历史功能和兼容性。数字对应其发布或试用时的构建。当前源码的运行情况见 [VALIDATION.md](../VALIDATION.md)。

## 2.1.1 · 源码交付与 WSL 安装

这版采用已验收的精简源码作为开发和交付入口。WSL 用户级 CLI 与 skill 链接指向同一份源码。模型格式和检查器版本延续 2.1.0。旧 Demo、开发启动包装和逐文件 npm 检查入口归并到 `bin/rtlarch open`、`npm run check` 及固定上游基准。需要按主题试跑时，为 `check` 指定 `workspace`、`diagrams`、`verification` 或 `workflow`。`npm run arch` 与 `npm run rtl:test` 仍可用于已有操作。

升级时从源码交付目录按锁文件安装并构建。继续打开目标项目原有模型。遇到源构建版本变化，保存输入后显式对该项目执行 `open --restart`。保留已有 IR 1/2/3 模型与 hash、提案、布局、讨论和历史验证。

发布目录由工具从白名单生成。过往的安装命令及自动化文件名按其当时版本解释。现行用法见 [使用说明书](USER-GUIDE.md)。

## 2.0–2.1 的验证与兼容节点

| 版本或主题 | 当时的成果和边界 |
| --- | --- |
| 2.0.0 · 逐状态、多实例 | v2 scopes 按真实实例分开比较。局部重测和空映射发现不遮住其他旧失败。双实例上游试验发现可相互抵消的两处差异，端到端队列结果和单步比较分别判定。 |
| 阅读任务、候选与逻辑锥 | 主事务和局部状态投影保留原成员。显式反馈、并行和共享约束逐项审核。逻辑锥增加来源、优先级和同一引用的多个消费者；人工试读依旧单列。 |
| 回放加固与九配置扩展 | 修复参数位宽、常量禁用分支、空轨迹、等待时负载变化、旧检查器和时间排序。随后加入旁路和双槽，保留简单单槽。上游九组与两个用于验证敏感性的故障按固定分母验收。 |
| 对象协作、候选与预算 | 两种窗口尺寸实测连接详情、同一对象提问和分支恢复。独立预算和决策绑定候选版本，扩展 RAM 端口、bank、反馈延迟与持续流率。 |
| Skill 试用 | 固定上游 16 位双槽的独立 Agent 试用执行九个原版用例与波形核对。状态未知和在线运行受阻按实际记录。随后 FIFO 操作试用暴露了能力发现、重复展开和多指针预算问题。 |
| 2.1.0 · 能力发现与展开复用 | 预检区分 `NOT_DECLARED` 和 `UNSUPPORTED`，RAM 帧使用独立 `verify`。源文件展开可以复用于不同模型的显式核对，阅读任务保留已知缺口。四组正常 FIFO 的 20 个映射为单步 MATCH，提前提交的故障得到独立仿真复核。 |

## 初始时序样例

0.7.1 的历史实测针对固定 8 位、FIFO 深度 4、加三的 tiny-stream。空载先在 E0 接收，E1+ 结果可见，E2 消费。满时有一次只出不进，恢复后可同时进出。复位沿前接口屏蔽和复位沿后状态清零分别检查。该观察限定于原始定向用例和参数，时钟调度仅供仿真。现行 `npm run rtl:test` 运行原自检及其 TIMEOUT 负例。
