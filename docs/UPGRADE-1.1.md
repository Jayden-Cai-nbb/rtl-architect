# RTL Architect 1.1：由真实反馈驱动的阅读与 RTL 核对

目标是让用户能从图回到 Agent 写出的代码，理解状态和行为，并据此决定是否接受设计。绘图效率为这个过程服务。

## 已实现

- 普通单击只选中、显示详情及高亮相邻关系；不增加节点/边、不重算路由。内部信号详情也有独立的“查看输入依赖”入口。
- 显式依赖追踪默认一层，遇到寄存状态停止；支持继续一层、跨状态继续。深度/规模限制会说明，原模型连接没有被删除。packed 输入集合不冒充字段级组合锥。
- 浏览器使用可终止的绘图 Worker；新请求取消旧任务，几何缓存按模型版本、层级、位置和展开配置区分，最多保存 8 份。缩放和选择不进入缓存键。初次绘图时仍可阅读详情。
- 密集小图按边数收紧额外通道与搜索预算；简化路径保留避障，无法绕行继续显示缺口。内部依赖按完整端点/位域去重，线名可追到来源。
- 寄存状态默认可见；内部节点支持独立位置、阅读主线及阶段背景。阶段不改变实例层级、模型 hash 或批准。候选可拖动并下载展示布局。
- 在线和 SVG 使用同一图形结果；导出当前图不再次同步走线。旧模型和旧布局保持可读，新增展示字段可选。

## Skill 的变化

入口围绕“一条主路径、真实状态边界、一个可观察验收场景”交付，再按问题深入。现状还原不能把实例树正确当作行为完整；不伪造寄存级，也不把不支持的组合运算建成 register。实现前读取项目规范，说明更新条件和同时条件优先级，核对被取消事务的副作用、前递选择及完成信号实际含义。TB 层级引用失配、断言失败、编译完成和器件验收分别报告。

## 如何使用

保存页面未发送内容后，在需要更新的工作区运行 `rtlarch open --workspace <项目> --restart`。其他工作区不自动重启，历史 HTML 仍为旧快照。

单击模块看职责 → “查看直接连接” → 必要时“再追一层”或“跨状态继续”。“寄存状态”与“内部逻辑”分别控制显示。调整候选的位置后点击“下载布局”；下次导入同版本布局即可。

独立 layout 的 `reading.mainPath/control/adjacent` 接收直属模块 ID 或 `local:<scope>:<id>`。可选 `stages` 为 `{id,label,nodes,note}` 列表，节点只能属于一个分区。约束带模型 hash，旧版本必须核对后重新导入。完整规范见 [框图阅读方法](../.agents/skills/rtl-architect/references/diagram.md)。

## 验证与边界

本轮记录见 [VALIDATION.md](../VALIDATION.md)。新增通用回归验证普通选择不改变几何、寄存边界截断与显式跨越、依赖去重、局部位置/阶段与 SVG 一致，以及密集图搜索与避障。真实项目材料仅在本机反馈目录中验证，没有加入公共样例。

这不是通用 HDL 行为解析器或时序证明器。未导入的组合逻辑仍会形成缺口；阶段位置不表示拍数。大规模互连仍可能有隐藏线名或简化路径，需按事务追踪检查，不以几何检查代替阅读。
