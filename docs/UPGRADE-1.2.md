# RTL Architect 1.2：按设计关系组织框图

1.1 把真实状态留在了图上，但逐输入的虚线、拥挤锚点和等权排序仍容易把架构画成线网。1.2 调整阅读层次、摆放约束和路由，帮助读者沿事务理解代码。

- **关系先于信号细节**：内部依赖改为实线；同来源、同目的、同显式用途的依赖收成关系束。点击“N 项”查看全部端口、数组索引和位域，不重新排图。未声明用途的接口保留独立身份。关系束不表示物理总线。
- **按主线安排位置**：数据与请求优先决定拓扑顺序，返回关系保留；控制和局部存储按声明及实际连接安排。不同宽度的并行节点仍属同一层，避免重新对齐时重叠。
- **阶段参与布局**：有依据的 `reading.stages` 约束分区顺序，区内按依赖排列，控制置于所属区域上方。短的寄存前路径可在区域内纵向折叠，寄存状态靠右；阶段不新增 RTL 实例或时钟周期。
- **为线和名字留空间**：四侧端口同时比较横纵距离；优先少折点正交通道和外围长返回。线名宽度参与间距，拥挤线名可用短引线放到邻近空位。在线和 SVG 共用几何。
- **大图可以读**：首次大图最低使用 65% 比例，右下角导航可点击、拖动及缩放；“全图”用于总览，“阅读大小”显示模块接口。离线页同样从可读比例进入，可滚动、缩放和展开关系成员。

默认主图还保留驱动模块的局部组合逻辑，避免隐藏选择器而让写回等通路无故断开。寄存器输入集合仍不等于字段级组合锥；未建模逻辑继续列为缺口。

## 使用

更新工具并保存页面未发送的内容后，在目标项目运行：

```bash
rtlarch open --workspace /path/to/project --restart
```

已有完整位置保留；点击“自动布局”才应用新的摆放规则，可撤销。需要表达阶段时导入带当前模型 hash 的独立 reading 布局，再自动布局。候选布局可下载，无需提交架构。历史 HTML 是固定快照，需用 `bundle` 生成新目录。

Skill 默认先说明本图要解释的事务、状态归属与返回路径，再组织主线和关系束，并在实际窗口追踪验证。参考 [框图阅读方法](../.agents/skills/rtl-architect/references/diagram.md) 与 [本轮验证](../VALIDATION.md)。

布局只使用模型中已声明的用途、连接和独立阅读约束，不从模块名字猜语义。复杂互连仍可能拥挤；几何通过、折点减少和截图都不能证明 RTL 正确，也不保证任意输入一次达到样稿效果。
