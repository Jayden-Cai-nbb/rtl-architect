在同一版本的本组夹具中，默认布局→显式阅读布局：仲裁交叉 8→5，共享 RAM 12→3，FIFO 12→7；其余三例均为 0。所有三种视图无重叠、穿框和未路由；架构/内部模式没有未排下线名。原始连接模式仍有部分隐藏长名称，详见逐例 quality；这不构成任意 RTL 改善比例或人类效率结论。

实际审图发现并修正了对端同名分组导致目标操作数共用锚点的问题，最终图中 a/b 分开；共享 RAM 返回采用相邻面。仲裁同时强制两条授权外绕反而增加交叉，最终仅较远的 B 授权外绕。机器几何通过不足以发现这些阅读问题，因此仍需沿事务检查。

维护中源码变化曾触发临时服务的 `SERVICE_BUILD_MISMATCH`；固定源码后入口复跑通过。浏览器脚本也修正了局部状态详情关闭后的测量等待；最终报告对应最终构建。早期日志 `build.log`、`layout-constraints.log` 保留执行时态，不代表收尾后又执行了全部检查。
