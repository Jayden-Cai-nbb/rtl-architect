# 让框图解释设计

图先解释模块分工与流向，完整职责、端口、位域和源码在点选后查看。主图、离线阅读页和 SVG 共用模型与路由，不能另画一张看似漂亮却对应不上连接的图。

## 先确定这张图回答什么

系统分工、模块微架构和逐拍行为的详细程度不同。先选真实层级，再说明输入如何经过运算、状态保存和输出；子系统沿层级进入，同构叶数组显示真实实例数。详细电路图可以解释寄存器、RAM、MUX，但必须有模型和 RTL 依据，不能装饰性添加寄存级。

总览的模块框只放短职责名和类型；放大到阅读比例后，在模块内部靠近真实锚点显示接口名，缩小时收起。为名称预留固定空间，缩放不改模块位置或端口；长职责、参数、路径留在详情。未知名称保留原名，不能自行发明用途。需要修改名称或 interfaceGroups 时按[阅读整理](reading-refinement.md)生成独立候选；纯位置、缩放和走线调整使用独立 layout，不改变模型或批准。

先组织空间，再检查线名：

- 主通路保持一致方向，相关运算和存储相邻。同类块对齐，控制通常在主通路上方，局部存储靠近使用者。
- 反馈和完成返回留外侧通道，请求、数据返回、写回各保留方向。横向顺序不能假造不存在的串行依赖。
- 白底、轻边框、少量含义固定的颜色。正常窗口要能读名称；“塞进一屏”不能替代阅读大小和可平移的图。
- 在图旁直接写“读请求”“读返回”“结果写回”等有依据的短名称。不要用 R01 编号和长对照表承担主要解释，也不能因为放不下而随机省略名字。

这种组织方式参考 [AMD AXI DMA 图 1-1](https://www.amd.com/content/dam/xilinx/support/documents/ip_documentation/axi_dma/v7_1/pg021_axi_dma.pdf#page=5)、[CV32E40P 框图](https://github.com/openhwgroup/cv32e40p/blob/master/docs/images/CV32E40P_Block_Diagram.svg)与 [OpenTitan AES](https://opentitan.org/book/hw/ip/aes/doc/theory_of_operation.html#block-diagram)。借鉴职责分区、就地命名和状态表达，不照搬配色、流水级或复杂度；这不是统一行业外观标准。

## 线与端口必须能追溯

一个连接束只聚合同源、同目的、同声明组的连接，保留全部真实 ID。×N 表示连接条数，不是位宽；单条连接不加多余的“×1”。分组是阅读组织方式，不意味着新增 RTL 总线。

内部驱动另以“关系束”展示：同一来源对象到同一内部状态/组合节点，按显式业务类别聚合；未声明用途的接口保持独立。N 项表示去重后的来源端点（包括索引和位域），点击显示全部成员。跨多个已声明组时用“控制依赖”等类别短名，完整端点在详情中；这不表示物理线网，也不证明 packed 寄存器的逐字段关系。正常依赖用实线，不把密集的逐输入虚线当总览。

四侧端口随显示位置安排，保持实际 source/target 不变。往返接口用各自箭头。先比较相对位置和绕行代价，左侧来的状态应优先从控制器左侧接入，右侧同理；上下对齐时再选择外围返回。控制端口不能因为“是返回信号”而统一塞到右侧。这些是显示规则，不是时序或组合环判断。

实心点只用于**真实来源端点集合相同**的分叉，不能仅凭颜色、组名或模块相同画成一个驱动。这样的同源分支可以共用已显示的名称，质量记录列出名称关联；普通交叉留白断开，不代表相连。所有分支仍可点选追溯。

内部寄存状态和驱动子模块的局部组合逻辑默认可见，其余组合细节按需展开。不要把流水寄存器与零散常量一起藏掉，也不要为了让图连通虚构未建模的表达式。左右边界按本层接口用途列组，不生成几十个独立端口框。仅显式 configuration/clock_reset 默认折叠，控制与数据默认可见。内部常量、拼接和局部寄存驱动标为内部逻辑，不计入 RTL 子模块；折叠项有入口和数量，导出保留 partial 与版本。

## 从普通输入得到可读的起点

这也是新设计和 RTL 还原的默认步骤。先按源码/展开结果建立真实层级，再根据生产者、消费者和事务阶段整理各层接口。已有模型仅做阅读优化时，按阅读整理的字段边界提案；不要顺手重分类 kind 或修改时序。

| 结构证据 | 阅读安排 |
|---|---|
| 前后级真实数据依赖 | 从左到右；并行分支并列，汇合保留多个来源 |
| 明确的控制模块和启动/完成关系 | 控制放上方，完成与取消保留各自方向；同时处理数据的模块保留在主结构 |
| 只有一个使用者的局部存储 | 靠近该使用者；共享存储或通路内存储保留全部访问关系 |
| 仲裁、多主设备、环形或递推 | 保留拓扑和反馈；不编造一条覆盖所有模块的 mainPath |
| 接口用途尚未核实 | 原端口名与真实连接先可见；不用 clk/config 等名字推断可折叠类别 |

分组依据是一次事务中的作用与信号配合，不是名称前缀、同位宽或相同协议。请求、返回、写回、控制与配置分别说明；每个组能追到原接口。跨模块同用途可统一短名称，不把多个独立驱动解释成单一总线。无法确定时保持未分组，说明缺哪些证据。

没有 reading 时，在线和离线共用自动布局：依据已声明 kind 和可见连接安排控制与局部存储，主结构优先按数据/请求及状态依赖分层，反馈不强迫主线倒序；用于排序的约束不是新增电路线。按邻接数量、实际线名宽度留间距，并重新测量四侧端口尺寸。它不改 IR、不推导业务含义，也不保证复杂互连无交叉。未分组接口显示原名，不合成笼统的“信号”。完整保存位置和显式 reading 优先；旧布局要点击“自动布局”或重新生成未指定布局的成果包才会应用新规则。

对每个需要交付的层级先用默认布局；只有阅读主线与拓扑安排不符时才补 reading。先修正有依据的分组，再调整布局和空间；不要用缩小文字掩盖密度。保留滚动、层级进入、端口放大和点选追踪。大规模交叉互连或来源缺失时，交付当前可读范围及具体限制，不能承诺任意 RTL 一次就达到样稿效果。

## 使用有依据的阅读布局

独立 layout 的 reading 描述 modelHash、reason、mainPath、control、adjacent。mainPath 是从左到右的本层对象：直属模块 ID 或 `local:<scope>:<id>` 内部节点引用；control 在上方；adjacent 的 node 靠近 mainPath 的 anchor 下方。未分配模块仍保留。只填写有设计依据的约束，不从名称猜测数据依赖。

```json
{
  "schemaVersion": 1,
  "scopes": {
    "top": {
      "positions": {}, "viewport": {"x": 0, "y": 0, "zoom": 1},
      "reading": {
        "modelHash": "本次模型的完整hash",
        "reason": "依据已核实的数据与存储关系安排",
        "mainPath": ["input", "compute", "output"],
        "control": ["scheduler"],
        "adjacent": [{"node": "history", "anchor": "compute"}]
      }
    }
  }
}
```

`bundle --layout <文件>` 只读生成新阅读包。完整 positions 优先；空位置按 reading 排列，结合端口尺寸预留模块间距。GUI 导入后预览，“保存布局”持久化已保存模型的布局；候选也可拖动和“下载布局”，下次按同一模型版本导入，无需提交设计；自动布局使用载入的 reading，可撤销。旧模型约束须核对后更新，不盲目复用。不直接改正在服务的布局文件。

`positions` 同样接收 `local:<scope>:<id>`。`reading.stages` 可写 `{id,label,nodes,note}`，nodes 使用相同引用，按列表顺序形成阅读区域，区域内依据主线和真实依赖安排，control 放在所属区域上方；阶段约束优先于跨区 adjacent。区域是阅读背景而非新模块；每个对象只归属一个分区，共享资源保持一个对象与真实反馈。引用范围和 modelHash 必须核对，阶段名字来自源码/合同，不从模块名字猜。mainPath 中的局部组合节点会显式显示。

走线要留出阅读间隔，长距离平行线不应贴在一起。空间不足时扩大布局并提供滚动阅读，不强行压成一屏。密集图限制搜索工作量；退到简化路径仍检查避障，并在页面提示。未找到路径继续算图形缺口，不能当作正常连线。优先使用少折点的正交通道，长返回优先外围；端口相对位置决定选边，不能只看上下偏移忽略左右距离。拥挤线名可用短引线移到旁边的空位；离线导出共用同一路径与标签坐标。当前路由以 32 图坐标单位为长平行线间距目标，端点附近和复杂绕行不保证固定最小值。

在线普通选择只选中及更新详情，不改变拓扑或走线；点击内部关系束展开成员，也不自动递归追踪。通过“查看直接连接”进入一跳追踪，“再追一层”扩展组合关系，“跨状态继续”才越过寄存器。深度和规模上限会明确提示；全部模型连接仍保留。后台计算可取消，选中/缩放不重做走线。首次打开大图最低采用 65% 阅读比例，可平移并用右下角全图导航；“全图”是查看整体分布的可选动作。已有保存视口保持用户选择。在线图支持选择信号、返回层级和阅读大小。离线页可切换层级、全图/原尺寸与缩放按钮；滚轮滚动、Ctrl+滚轮缩放，双击模块放大居中。缩放达到 90% 后显示内部接口名，可点名称追踪该端口的连接；多个接口共用锚点时显示首个名称与其余数量，完整名称仍可查。SVG 导出保留当前详略状态，成果包的独立 SVG 包含原尺寸接口名。所有操作保持同一几何，不修改架构。

## 按实际阅读验收

先看一个顶层和一个复杂子层级的实际样稿，再推广通用样式。打开正常尺寸的页面和导出 SVG，沿一条关键事务确认：输入交给谁，谁存状态，谁发请求、谁返回，完成与取消走哪里。学习讲解围绕这条真实路径展开，按用户兴趣深入，不设置强制测验。

检查标题与线名是否被遮挡，分叉与跨线是否可辨，箭头是否落在真实端口，局部逻辑与返回路径是否位于层级范围内。检查一次默认进入是否无需放大就能辨认模块和箭头，再点一条关系束核对成员，并沿返回路径找到状态更新者；发现布局误导时调整约束，不能靠降低线条透明度掩盖。

同时检查数组非首索引、未知与缺口；短说明不能删掉推断限定词。

quality.json 报告重叠、穿节点、未路由、未排下名称、共享名称及折叠范围。几何通过不表示名称一定可读；遇到未排下名称，先调整间距和通路，不能把隐藏当作完成。复杂互连仍可能有交叉，应在页面中实际追踪，不能用交叉数、hash 或数量代替人工阅读。

模块框不等于寄存级，图中距离不表示延迟。需要解释周期时按[时序方法](timing.md)和[逐拍实例](timing-example.md)核对接受沿、真实状态、结果可见与消费沿，连同地址/tag/valid 一起追踪；派生说明带模型版本，不成为第二份合同。SVG 和截图不证明 RTL 行为或 STA。

有交互卡顿反馈时，分别测选择、布局、走线与绘制；先复现再归因。普通选择验收包括节点/边数与路径不变、详情及时更新；显式展开检查后台任务取消、过期结果与模型/位置变更后的缓存失效。多轮中位数/p95 与单次测量分开，不能拿其他机器的旧报告声称本轮提速。
