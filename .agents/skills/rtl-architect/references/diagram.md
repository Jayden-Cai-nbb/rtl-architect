# 让框图解释设计

图先解释模块分工与流向，完整职责、端口、位域和源码在点选后查看。主图、离线阅读页和 SVG 共用模型与路由，不能另画一张看似漂亮却对应不上连接的图。

## 先确定这张图回答什么

系统分工、模块微架构和逐拍行为的详细程度不同。先选真实层级，再说明输入如何经过运算、状态保存和输出；子系统沿层级进入，同构叶数组显示真实实例数。详细电路图可以解释寄存器、RAM、MUX，但必须有模型和 RTL 依据，不能装饰性添加寄存级。

总览的模块框只放短职责名和类型；放大到阅读比例后，在模块内部靠近真实锚点显示接口名，缩小时收起。为名称预留固定空间，缩放不改模块位置或端口；长职责、参数、路径留在详情。未知名称保留原名，不能自行发明用途。需要修改名称或 interfaceGroups 时按[阅读整理](reading-refinement.md)生成独立候选；纯位置、缩放和走线调整使用独立 layout，不改变模型或批准。

先组织空间，再检查线名：

- 主通路保持一致方向，相关运算和存储相邻。同类块对齐，控制通常在主通路上方，局部存储靠近使用者。
- 反馈和完成返回留外侧通道，请求、数据返回、写回各保留方向。横向顺序不能假造不存在的串行依赖。
- 白底、轻边框、少量含义固定的颜色。正常窗口要能读名称；“塞进一屏”不能替代阅读大小和可平移的图。
- 在图旁直接写“读请求”“读返回”“结果写回”等有依据的短名称。不要用 R01 编号和长对照表承担主要解释，也不能因为放不下而随机省略名字。

这种组织方式参考 [AMD AXI DMA 图 1-1](https://www.amd.com/content/dam/xilinx/support/documents/ip_documentation/axi_dma/v7_1/pg021_axi_dma.pdf#page=5)、[CV32E40P 框图](https://github.com/openhwgroup/cv32e40p/blob/master/docs/images/CV32E40P_Block_Diagram.svg)与 [OpenTitan AES](https://opentitan.org/book/hw/ip/aes/doc/theory_of_operation.html#block-diagram)。借鉴职责分区、就地命名和状态表达，不照搬配色、流水级或复杂度；这不是统一行业外观标准。

## 线与端口必须能追溯

一个连接束只聚合同源、同目的、同声明组的连接，保留全部真实 ID。×N 表示连接条数，不是位宽；单条连接不加多余的“×1”。分组是阅读组织方式，不意味着新增 RTL 总线。

四侧端口随显示位置安排，保持实际 source/target 不变。往返接口用各自箭头。先比较相对位置和绕行代价，左侧来的状态应优先从控制器左侧接入，右侧同理；上下对齐时再选择外围返回。控制端口不能因为“是返回信号”而统一塞到右侧。这些是显示规则，不是时序或组合环判断。

实心点只用于**真实来源端点集合相同**的分叉，不能仅凭颜色、组名或模块相同画成一个驱动。这样的同源分支可以共用已显示的名称，质量记录列出名称关联；普通交叉留白断开，不代表相连。所有分支仍可点选追溯。

左右边界按本层接口用途列组，不生成几十个独立端口框。仅显式 configuration/clock_reset 默认折叠，控制与数据默认可见。内部常量、拼接和局部寄存驱动标为内部逻辑，不计入 RTL 子模块；折叠项有入口和数量，导出保留 partial 与版本。

## 使用有依据的阅读布局

独立 layout 的 reading 描述 modelHash、reason、mainPath、control、adjacent。mainPath 是从左到右的直属模块；control 在上方；adjacent 的 node 靠近 mainPath 的 anchor 下方。未分配模块仍保留。只填写有设计依据的约束，不从名称猜测数据依赖。

```json
{
  "schemaVersion": 1,
  "scopes": {
    "top": {
      "positions": {}, "viewport": {"x": 0, "y": 0, "zoom": 1},
      "reading": {
        "modelHash": "本次模型的完整hash",
        "reason": "依据已核实的数据与存储关系安排",
        "mainPath": ["input", "compute", "output"],
        "control": ["scheduler"],
        "adjacent": [{"node": "history", "anchor": "compute"}]
      }
    }
  }
}
```

`bundle --layout <文件>` 只读生成新阅读包。完整 positions 优先；空位置按 reading 排列，结合端口尺寸预留模块间距。GUI 导入后预览，“保存布局”才持久化；自动布局使用载入的 reading，可撤销。旧模型约束须核对后更新，不盲目复用。不直接改正在服务的布局文件。

走线要留出阅读间隔，长距离平行线不应贴在一起。空间不足时扩大布局并提供滚动阅读，不强行压成一屏。当前路由以 32 图坐标单位为长平行线间距目标，端点附近和复杂绕行不保证固定最小值。

在线图支持选择信号、返回层级和阅读大小，选择不重新排模块。离线页可切换层级、全图/原尺寸与缩放按钮；滚轮滚动、Ctrl+滚轮缩放，双击模块放大居中。缩放达到 90% 后显示内部接口名，可点名称追踪该端口的连接；多个接口共用锚点时显示首个名称与其余数量，完整名称仍可查。SVG 导出保留当前详略状态，成果包的独立 SVG 包含原尺寸接口名。所有操作保持同一几何，不修改架构。

## 按实际阅读验收

先看一个顶层和一个复杂子层级的实际样稿，再推广通用样式。打开正常尺寸的页面和导出 SVG，沿一条关键事务确认：输入交给谁，谁存状态，谁发请求、谁返回，完成与取消走哪里。学习讲解围绕这条真实路径展开，按用户兴趣深入，不设置强制测验。

检查标题与线名是否被遮挡，分叉与跨线是否可辨，箭头是否落在真实端口，局部逻辑与返回路径是否位于层级范围内。同时检查数组非首索引、未知与缺口；短说明不能删掉推断限定词。

quality.json 报告重叠、穿节点、未路由、未排下名称、共享名称及折叠范围。几何通过不表示名称一定可读；遇到未排下名称，先调整间距和通路，不能把隐藏当作完成。复杂互连仍可能有交叉，应在页面中实际追踪，不能用交叉数、hash 或数量代替人工阅读。

模块框不等于寄存级，图中距离不表示延迟。需要解释周期时按[时序方法](timing.md)和[逐拍实例](timing-example.md)核对接受沿、真实状态、结果可见与消费沿，连同地址/tag/valid 一起追踪；派生说明带模型版本，不成为第二份合同。SVG 和截图不证明 RTL 行为或 STA。
