# 证据与当前成果入口

## 四种状态分开读

| 状态 | 来源 | 能说明什么 |
|---|---|---|
| 架构批准 | 当前模型、模块确认、整体批准 | 人批准了哪版设计；不代表 RTL 已验证 |
| 来源新鲜度 | `rtlarch evidence` 重新计算声明文件 SHA-256 | 字节匹配、变化、缺失或无法读取；变化不自动等于行为变化 |
| 实现验证 | 指定运行的输入 manifest、退出状态和结果 | 哪些配置、输入、seed、扰动及属性验证过 |
| 器件验收 | 指定输入的约束、综合/布局布线和 STA 报告 | 资源与物理时序范围；综合资源不等于布线后 STA |

`evidence --workspace <项目> --json` 不启动服务、不改来源或批准。任一来源异常返回非零；无声明证据返回 unknown，不能当作全部新鲜。候选用 `--model <完整模型.json>`。检查只覆盖声明文件，不自动发现全工程依赖。变更后分析影响，必要时补提案或重跑，不自动更新摘要消除提示。

运行证据放项目既有保留目录（例如 `verification/runs/<runId>/` 或 `docs/evidence/<runId>/`），不要让 clean 可删除目录成为唯一来源。最低记录 argv/cwd、工具版本、起止时间、退出状态、modelHash、RTL/TB/Golden/配置/约束摘要、seed、结果摘要。先保存输入快照或核对运行前后摘要；运行后才补当前文件 hash 无法证明历史输入。复用项目运行器，不另造 EDA 平台。

通过条件同时检查退出状态、自检完成、用例数量与必要产物。零测试、全跳过、超时、缺报告、换 run 或输入不匹配不能算通过。指标从选定报告解析；手填值必须注明人工录入及来源。Golden 负责数值，协议/时序/取消需要独立检查。

## 一个可离线阅读的入口

```bash
rtlarch bundle docs/architecture/<本次目录> --workspace <项目> --json
rtlarch bundle proposals/<本次目录> --model proposals/design.json --workspace <项目> --json
```

目录必须是新的，工具拒绝覆盖以及写入 architecture/generated/.rtlarch。模型及批准记录只读；生成 index.html、README.md、Spec、contract.json、model.json、各子系统 SVG、完整连接索引、质量记录、evidence.json 和产物 hash manifest。合同副本供阅读，不取代 `handoff` 对正式合同的核验。候选即使内容与当前相同也标为候选，不借用批准状态。

入口提取用途、分工、决定及理由、需求验收和待定问题；验证栏目只展示模型中声明的历史记录，外部实现记录未自动接入时明确“未核验”。agent 在交付说明中补充已核对的指定 run 结果及下一步，不能让工具按自由文本猜“已达标”。预算保持设计时态，不用后验测量覆盖合同。

`--layout <布局.json>` 可选符合 `schema layout` 的展示布局；它不改变模型。默认使用当前保存布局（候选默认重新布局），缺少位置的层级使用公共布局器。完整映射、折叠、隐藏标签和路由失败在质量记录中公开。严重几何错误返回 DIAGRAM_QUALITY_FAILED 并保留诊断包；隐藏标签有离线索引，不等于图已通过人工阅读。

交付前检查：入口能找到当前版本和下一步；图/Spec/合同的完整 hash 一致；每条声明连接可追到真实端点；证据链接可用；正常与扰动事务可解释。几何统计不替代浏览器阅读，未执行就写未执行。四种状态不合并成一个绿色 PASS。

需要持久保存方案预算、执行本次验证或继续前一会话时，按 [持续工作](workbench.md) 使用 study / verify / resume。计算下界、当前输入下的实际运行、历史日志和人工批准分别报告。
