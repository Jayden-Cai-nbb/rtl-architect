# 把旧候选整理成能讲清设计的候选

适用于 summary 在讲工具进度、name 全是 inst_*、职责复制源码账本、分组只有 data/control 等情况。目标是读者能从输入到输出复述处理流程，再判断设计；不是把未知包装成确定结论。

## 先固定整理边界

读取当前工作区和需要修订的完整候选。记录两者各自的 hash；原候选文件与登记记录不覆盖。核对候选的输入配置、来源摘要及相关 RTL/TB，不能因名称眼熟就沿用已变化源码的旧描述。

默认允许整理 design.name、specification.summary、module.name、contract.responsibility、interfaceGroups 和 interfaces[].group。其余字段保留，包括稳定 ID、rtlModule、层级、数组范围/覆盖、参数/绑定、端口方向/位宽/协议/必连性、连接/切片、局部驱动、时钟复位、所有 provenance，以及已有需求、行为合同和未决问题。

“改职责文字”也可能改变含义；字段检查只能保护结构。不要删去原职责中唯一记录的限制、前提或未知。发现行为描述错误、时序缺失、证据缺失或分组实际不符时，单独列出需要补证/修正的范围。补证会改变 provenance，补时序会改变 contract；均通过独立提案审阅，不冒称纯阅读整理。若用户同时要求两类工作，先保存阅读候选文件，再从它生成时序补充候选供 A/B 核对；这不表示提交工作区。

## 从顶层逐层解释

顶层 summary 用一小段讲输入、主要处理阶段、输出与结束条件。子系统解释直接子模块如何协作，指出存储/调度的状态归属和主要请求/返回/写回。叶模块说明实际变换或保存的内容，不把父层职责重复一遍。

| 原有表征 | 整理目标 | 核对位置 |
|---|---|---|
| “0.5试用，原生数组，partial” | 说明设计在做什么；原导入进度继续留在来源与覆盖记录中 | 顶层端口、实例与控制逻辑 |
| “inst_buffer” | 有依据时用“输入队列”等职责名；原实例ID与rtlModule保持 | 实例连接、存储/指针更新 |
| “读取数据，完成处理” | 谁触发读取、返回什么、由谁消费；未知延迟仍写未知 | 使能、地址、返回valid与消费者 |
| 大组“data/control” | 将同一任务的地址、使能、数据组织成“读取请求/结果返回”等阅读组 | 每个原端口的具体使用与连线 |

这些名称只是例子，不照抄到任意项目。分组要逐项映射原端口，说明为什么属于同一用途。数据与valid即使放一组也不自动成为 rv；旁带、广播、反馈和未使用输入仍保留。时钟/配置类别会影响默认折叠，不能用它隐藏难解释的控制或数据。

先更新顶层，再进入各子系统直到叶模块；同构数组用共享职责，存在元素差异则明确索引范围。每层核对“只读此层的职责和子块，能否说清处理过程”。没有看过的层级列为未整理，不能只改三块名称就声称全项目完成。

## 检查并生成独立提案

在任意项目目录执行本 skill 自带的只读检查（路径按实际安装位置解析）：

```bash
python3 <skill目录>/scripts/check_reading.py proposals/before.json proposals/reading.json
rtlarch compare proposals/before.json proposals/reading.json --json
rtlarch draft proposals/reading.json --workspace <项目> --open --json
```

脚本输入是两个完整 Model，不是 Proposal 或 API 包装。输出 JSON 和文件字节 SHA-256（不是 modelHash）；退出0表示只动允许字段，1表示受保护字段变化，2表示输入错误。允许被检查的具名对象重排，拒绝这些对象的重复 ID 和任何重复 JSON 键。脚本不校验完整 Schema、不证明文字等价、不联网或写文件；仍需工具预览及源码审阅。Python3 不可用时按同一字段边界人工核对并说明未运行脚本。

不要为使检查通过而删去必要修正；把它分成清楚的后续提案。登记前后的基线应一致，当前模型变化则按提案约定恢复。

## 审阅者如何判断整理是否有效

从顶层选一笔输入，解释它经过哪些模块、在哪里保存、何时输出；再追一条反向控制/反馈。进入子系统后应延续同一故事，而不是重新学习一套命名。点组能找到原端口与来源，原来的冲突和未知也能找到。

交付说明列出已整理层级、未整理范围、名称/职责/组的差异和需人确认的词义。给出新旧候选比较、校验与 reviewUrl；不自动保存或批准。关于延迟、吞吐、阻塞、复位的进一步解释按 [时序方法](timing.md) 单独补齐。
