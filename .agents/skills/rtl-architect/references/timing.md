# 从 RTL 解释电路时序

用于还原、设计、时序审阅和实现交接。先回答“哪一笔数据，在什么条件下，于哪个沿被保存或消费”，再讨论频率。只分析当前任务涉及的路径；选择能区分实现的情景，不机械生成所有组合。

## 先约定怎么计时

将所分析时钟的有效沿记为 E0、E1……；下降沿采样、多相或多时钟设计分别命名，不能共用一个虚构的周期编号。`E0−` 是采样前稳定值，`E0+` 是该沿寄存更新并经组合逻辑稳定后的值，不是零物理延迟。

| 事件或量 | 必须说明 |
|---|---|
| 输入接受 | 哪个时钟沿、什么使能/握手条件；请求出现不等于已接受 |
| 结果可见 | 数据与有效标志何时一起可被观察；无效周期的数据不视作结果 |
| 输出消费 | 哪个沿被下一模块/外部接收；可见但阻塞时仍是同一笔事务 |
| 延迟 | 从哪个接受事件到哪个可见/消费事件；空载、排队、背压前提 |
| 启动间隔 | 最短多久能接受下一笔；它与单笔延迟不同 |
| 吞吐 | 在何种持续输入、下游准备好及存储供给条件下成立 |

例如在 E0 接收、E0+ 出现寄存结果、E1 才被下游采样，按“接收沿→消费沿”计为1拍，不能写成“输出在E0可见，所以零拍”。纯组合路径可能同沿完成边界握手，但必须核对真实组合依赖及采样条件。

## 从状态和寄存边界出发

读取有效配置下的 always/always_ff/always_comb、连续赋值、RAM/IP 配置以及 TB 的驱动/采样位置。为影响当前路径的状态记下：所属模块、时钟沿、复位、更新条件、优先级、下一值来源。表格可作推导草稿，关键结论写回合同与来源记录。

非阻塞赋值的右值在语句执行时求值，左值稍后更新。对 `a <= x; b <= a;`，b取得更新前的a；不要把同沿执行的模块当作顺序调用。若过程混用阻塞临时变量、多个条件重复赋值、或多过程写同一对象，要按实际调度/优先级核对并指出冲突，不能一律按“每行加一拍”解释。

组合逻辑、实例边界、assign、generate 和函数调用不自动增加寄存级。FSM 状态切换要区分用旧状态生成的控制、更新后的状态，以及控制是组合输出还是寄存输出。Moore/Mealy 等名称不替代实际事件追踪。

从接受事件沿路径标出真实存储边界，分别追踪 data、valid、地址、tag/ID、last/mask 等相关信息。遇到 mux/仲裁/可变延迟分支，以事务身份核对汇合，不仅比较寄存器数量。反馈指出经过哪个状态保存和何时再次使用；模块图有环不等于组合环，含寄存器也不能排除其他组合旁路。

## 为关键情景画逐拍表

对相关路径选择正常、持续输入、阻塞恢复、复位中止；涉及队列或存储时再看空/满、同时读写、地址冲突。统一表头可用：

| 沿 | 沿前状态/有效数据 | 该沿实际接受或消费 | 沿后状态/输出 | 前提与依据 |
|---|---|---|---|---|
| E0 | …… | …… | …… | 文件/合同/实测记录 |

每行标出事务A/B或明确地址，不只填0/1。停顿不是把所有模块统一暂停：分别核对谁保持、谁还能接收、返回数据存在哪里、容量是否足够。没有 ready 的接口，写实际节拍约束、丢弃/覆盖行为或未知，不擅自加握手。

对有背压的有效数据，说明阻塞期间哪些字段必须保持、是否允许新输入替换旧输出，以及复位/flush如何取消该义务。无限外部阻塞下不能承诺有限消费延迟；输入接受以后也不等于一定完成，可能被复位中止。完成/中止应有可核对的守恒关系。

推导例子见 [逐拍实例](timing-example.md)。它展示计拍方法，不能当成其他项目的默认实现。

## 核对停顿、取消与副作用

若设计有 stall/flush/异常，按真实代码列一张短更新表：每个受影响状态在各条件下保持、装载、清零还是继续推进；写明条件同时成立时的优先级。不要统一写成“流水停止”，也不要假设所有设计都必须新增 valid。

核对与该事务绑定的寄存器写入、存储写入、外部请求和完成报告。被取消的年轻事务不能产生合同禁止的副作用；更早的事务是否允许完成由项目约定决定。前递/旁路要写来源优先级、命中条件及禁用条件，不能只画 mux。done/retire/trap 的名称不足以决定含义，实际赋值和下游消费才是依据。

将最危险的同时条件变成可观察测试，例如取消与写入同拍、停顿时返回仍到达、连续两笔写同一目标。先明确正确结果和观察沿，再实现或修改测试；不把图上的连线长短当成时序证据。

## 存储、复位与跨域重点

| 对象 | 容易误读的点 | 要落实的约定 |
|---|---|---|
| 同步 RAM/ROM | 地址寄存、RAM输出寄存和包装valid错位；“同步读”没说哪一沿 | 请求何时采样，哪拍返回，是否可连续请求、取消后怎样处理返回 |
| 同址读写 | RTL语句顺序、仿真模型、综合RAM模式不一致 | 实际 read-first/write-first/no-change 或未定义；核对目标IP/器件配置，不按名字猜 |
| FIFO | 空穿透与非穿透；满且出队时是否同时接收 | 从接受/消费谓词推导，单独核对满/空边界和读写同拍 |
| 锁存器/双沿逻辑 | 将电平透明窗口或半周期路径按普通上升沿流水线计拍 | 核对透明条件、关闭时刻及真实边沿关系；无法表达时列出缺口，不硬填整数拍数 |
| 时钟使能/门控时钟 | 把使能拉低当成组合输出也冻结，或把派生时钟当同一个域 | 区分寄存更新使能与真实时钟路径，核对停钟/恢复及毛刺保护的来源 |
| 异步复位 | 事件列表只能说明异步断言，不能证明同步释放 | 每域释放路径、恢复前首次允许接受/输出的沿；未知释放保留 unknown |
| RAM未复位 | 把指针/valid清零误说成阵列清零 | 哪些状态归零、哪些内容保留、何时内容重新有效；门控不是状态复位 |
| CDC/RDC | 同名时钟、相同标称频率或两个触发器被当成安全证明 | 真实域关系、单比特/脉冲/多比特传递方式和接收条件；不把独立同步的总线位当成一致字 |

异步域之间通常不能承诺固定端到端周期数；需要各域事件及握手说明。当前模型的单时钟绑定和连线检查不完整表达多域、生成时钟、门控时钟与跨域路径，也不做 CDC/RDC 证明。保留原始时钟定义与具体缺口，不把域合并成相同 clock 来通过校验。

## 写入现有 IR

| 内容 | 现有字段 |
|---|---|
| 实际采样边沿、状态复位与释放方式 | clocks/resets、module.clock/reset/timing/resetControlInputs |
| 空载周期下界 | contract.latencyMinCycles |
| 计拍起止、可见与消费区别、启动间隔、变量延迟条件 | contract.latencyCondition |
| 接受谓词、保持/覆盖、队列满空与阻塞恢复 | contract.backpressure、invariants |
| 清除/保留状态、在途取消、复位退出时首笔有效 | contract.resetBehavior |
| 逐拍可检查条件、输入扰动及超时条件 | verificationPlan、requirements.acceptance |
| 源码事实、推导前提、未知/冲突及范围 | provenance.findings/evidence/unsupportedStructures、openQuestions |

latencyMinCycles只能表示非负整数下界，不能表示unknown、最大延迟、半拍或多时钟换算。若确实无可证实的更强下界，只能以0表达保守下界，并在latencyCondition明确“实际延迟未知，0不表示零拍”，保留未决问题；不能因此宣称时序已完整。已知时钟与寄存类型但延迟未知时，不要把整个模块错误改成 timing=unknown。

周期表、寄存边界图和波形附件记录场景前提、模块ID、modelHash以及 sourceDigest/证据。正式合同只保留不依赖某次测试刺激的约定；具体轨迹是它的实例，不成为另一份可独立编辑的规范。更改模型后更新派生图，旧图保留旧版本标识。新来源/测量要通过提案加入provenance，不能悄悄把推断升级为事实。当前没有原生周期表、波形或自动时序求解字段，不向严格Schema塞自定义属性。

## 单独核对物理时序

周期行为正确之后，再检查目标频率与真实约束。读取工程的时钟/生成时钟、I/O delay、时钟不确定度、例外及适用对象；有实现结果时记录工具版本、配置、器件/工艺、阶段/角落、起终点、路径类别与slack。分别看setup、hold；涉及异步控制时核对recovery/removal等适用检查，以及未约束路径和例外覆盖。

组合运算深、宽mux、长ready反压路径、大扇出或跨模块往返是需要检查的候选瓶颈，不凭RTL视觉估算宣称频率。行为延迟N拍不自动允许N拍组合传播；多周期约束改变setup/hold边沿关系，需要起终点控制行为支持，不能为消掉违例随意加例外。[AMD UG903 多周期路径](https://docs.amd.com/r/2025.1-English/ug903-vivado-using-constraints/Multicycle-Paths)

TB的时钟周期、`--timing`仿真、波形看起来整齐都不是STA通过。Verilator的时间控制选项用于仿真事件调度；运行模型时还需按其时钟与求值接口正确驱动。[Verilator 时间控制](https://verilator.org/guide/latest/languages.html#time)、[模型求值说明](https://verilator.org/guide/latest/connecting.html#evaluation-loop)

没有相应工具、约束或报告时，将物理时序记为未验证/受阻，列出具体缺口，不编造Fmax或slack。增加流水级、调整缓存、跨域方法或时序例外都属于需说明影响的设计变更，遵守当前任务的审阅范围。

## 从解释走到验证

TB应区分采样前握手和沿后更新，避免与DUT在同一仿真区域竞态。按工程采用反相沿驱动或明确skew的clocking block等方式；不要随意加`#1`就声称证明了周期。异步复位还要检查沿间断言，而不是只在采样沿拉低。

选能揭露错误的检查：输出与对应输入/地址/tag一致；阻塞期间有效数据不变（明确复位/取消例外）；输入接受数=输出消费数+有效在途数+已取消数；同拍进出满足容量；空载达到约定延迟；持续负载达到所声明吞吐前提；没有无请求的过期返回。计数要在同一观察点比较。

把“源码推导”“本次仿真观察”“形式证明”“STA结果”分开。一个轨迹支持该配置和刺激的观察，不证明所有序列。验证失败先对照合同、RTL与TB采样约定定位；合同需要改变时回到架构提案，不能改测试期望掩盖行为差异。
